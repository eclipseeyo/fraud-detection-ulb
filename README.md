# Детекция транзакционного фрода (ULB Dataset)

## Задача
Разработка пайплайна машинного обучения для поиска мошеннических транзакций.
Цель - построить решение, которое можно внедрить в реальный антифрод. Основной упор сделан на работу с экстремальным дисбалансом классов (0.17% фрода) и имитацию реального времени.

## Технологии
- Модели: Logistic Regression (baseline), XGBoost (основная модель)
- Фреймворки: scikit-learn, XGBoost
- Обработка данных: Python, pandas, numpy
- Инструменты: Git, VS Code

## Данные и подготовка
Для обучения использован классический открытый датасет Credit Card Fraud Detection (ULB):
https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud

Датасет содержит 284 807 транзакций за два дня, из которых только 492 (0.172%) - мошеннические. Признаки V1-V28 анонимизированы через PCA, а `Time` и `Amount` - реальные числовые признаки.

## Анализ данных
В ходе исследования исходного датасета были выявлены следующие особенности:
1. **Экстремальный дисбаланс.** Соотношение классов 578:1. Это означает, что Accuracy здесь бесполезна.
2. **Временная природа данных.** Фрод распределен по времени неравномерно. Пик мошеннической активности приходится на ночные часы, когда общий поток легальных транзакций падает. На основе этого было решено добавить признак `Hour` (час суток).
3. **Анонимизация признаков.** V-признаки нельзя интерпретировать напрямую, но корреляционный анализ показал, что сильнее всего с целевой переменной связаны V17, V14, V12 и V10.

Эти особенности были учтены при построении пайплайна для исключения утечек данных и повышения качества финальной модели.

## Эксперименты и результаты

### Этап 1: Baseline и первые метрики
Для начала была обучена логистическая регрессия с `class_weight='balanced'`. Использовался **Time-Aware Split**: данные разбивались по времени (80% прошлое — train, 20% будущее — test). Это исключает утечку данных, ведь в реальной жизни модель не может обучаться на будущих транзакциях.

Результат на стандартном пороге 0.5 выглядел так: `Precision = 0.04`, `Recall = 0.91`. Модель ловила 91% фрода, но при этом блокировала огромное количество легальных клиентов. Это классическая ловушка дисбаланса, когда модель ловит всё подряд.

### Этап 2: Переход к XGBoost и подбор порога
Следующим шагом стал XGBoost с параметром `scale_pos_weight` (для компенсации дисбаланса). `PR-AUC` вырос с `0.766` (у логрега) до `0.784`. Однако `F1` при пороге 0.5 оставался низким.

Тогда внутри `train.py` была написана функция `find_best_threshold`, которая использует `precision_recall_curve` для перебора всех возможных порогов и поиска того, что дает максимальный F1. Оказалось, что для этой задачи стандартный порог 0.5 совершенно не подходит. Оптимальный порог сместился в район `0.92-0.97`, что позволило поднять `Precision` до `0.89-0.93` и увеличить `F1` с `0.08` до `0.81-0.84`.

### Этап 3: Подбор гиперпараметров
Чтобы выжать чуть больше, был написан скрипт `tune.py` с использованием `RandomizedSearchCV`. Главная сложность была в кросс-валидации: стандартный `KFold` здесь использовать нельзя (он перемешивает данные). Поэтому использовался `TimeSeriesSplit(n_splits=3)`, чтобы валидация всегда шла на "будущих" данных.

 `RandomizedSearchCV` успешно нашел лучшие параметры (`max_depth=6`, `learning_rate=0.05`, `subsample=0.7`), и итоговый тестовый `PR-AUC` вырос до `0.7939`.

## Сравнение моделей
- **Logistic Regression**: `PR-AUC = 0.7662`, `F1 = 0.0856` (порог 0.5). После подбора порога (`1.0`): `Precision = 0.89`, `Recall = 0.75`, `F1 = 0.8116`.
- **XGBoost (Tuned)**: `PR-AUC = 0.7939`, `F1 = 0.7755` (порог 0.5). После подбора порога (`0.923`): `Precision = 0.93`, `Recall = 0.76`, `F1 = 0.8382`.

На первый взгляд может показаться, что логрег и XGBoost дают почти одинаковый результат. Однако это объясняется PCA-признаками. XGBoost всё равно выигрывает по `PR-AUC` и лучше работает с нелинейными взаимодействиями (например, сумма + ночное время).

## Анализ ошибок и переобучение
При финальном пороге `0.923` модель показала следующие результаты на тесте (56 962 транзакции, из них 75 мошеннических):

Анализ ошибок показал:
- **Ложные тревоги (FP):** всего 5 транзакций. Интересно, что модель была в них уверена на 97%, но они оказались легальными. Такие случаи в реальном проде отправляли бы на ручную проверку, а не блокировали автоматически.
- **Пропущенный фрод (FN):** 18 транзакций. Самое важное наблюдение: медиана вероятности для них составила `0.006` (менее 1%). Модель была уверена, что это легальные операции, а это значит, что данные мошенничества хорошо маскировались под нормальное поведение. Наверное, для их отлова в реальном проде потребуются дополнительные признаки, которых в датасете ULB просто нет.

## Выводы

В ходе экспериментов были получены следующие результаты:
- Базовая модель (Logistic Regression): `PR-AUC = 0.766`, `F1 = 0.81`
- Финальная модель (Tuned XGBoost): `PR-AUC = 0.794`, `F1 = 0.84`

**Финальная модель показала уверенные результаты** (`PR-AUC = 0.794`) на сложных данных, что делает её более пригодной для использования в реальном продакшене, где условия всегда разнородны.

Главный вывод проекта: в антифроде гораздо важнее методология (правильный сплит, подбор порога), чем выбор конкретной "модной" модели.

## Как запустить
1. Клонировать репозиторий.
2. Установить зависимости: `pip install -r requirements.txt`
3. Скачать `creditcard.csv` по ссылке выше и положить в папку `data/`.
4. Запустить обучение: `cd src`, затем `python train.py`
5. Запустить анализ ошибок: `python error_analysis.py`
